# HDN Title Strategy 2026

HDNの記事タイトルは、単一の「うまいタイトル」を作るのではなく、検索・SNS・AI検索で役割を分けて設計する。

## 1. SEO / page title

- 誰のどんな疑問に答える記事かを最初に定義する。
- 検索意図を示す主要語は、意味を壊さない範囲で前半に置く。
- 固定の「30文字」「32文字」をSEOルールにはしない。重要な意味が前半で伝わり、簡潔でページ内容を正確に表すことを優先する。
- 数字、対象、制度名、固有名詞は、記事本文で裏付けられる場合だけ使う。
- 「とは」「違い」「やり方」「なぜ」等は、想定質問と自然に一致するときだけ使う。型の量産はしない。
- タイトルとH1、主要見出し、冒頭結論の主張を一致させる。
- キーワード反復、誇張、煽り、根拠のない最大級表現は禁止する。

## 2. SNS / Open Graph title

- `socialTitle` をSEOタイトルとは別に持てるようにする。
- タイムラインで意味が一読できる短さを優先する。20文字を絶対条件にはしない。
- 要約ではなく、記事内の最も強い「具体的な論点・逆説・問い・数字」を切り出す。
- 読了後に「タイトル通りだった」と言える範囲を超えない。
- 人を見下す表現、怒りだけを誘う表現、内容と乖離した謎かけは禁止する。
- 一人称は、実際の経験・判断として公開可能な場合だけ使う。AIに体験を創作させない。
- OGP画像と文言を一体で評価する。画像内テキストはタイトルの単純な重複にしない。

## 3. AI search / answer surfaces

- 特別な「AIO専用タイトル」を作るより、検索意図と本文の回答関係を明確にする。
- 冒頭で結論を提示し、H2/H3で論点を分解する。
- 具体的な事実、一次情報、日付、数字、条件、例外を明示し、引用・要約しやすい構造にする。
- タイトルだけを最適化せず、タイトル→冒頭回答→見出し→本文→FAQの意味を一貫させる。
- 独自の実務知見は価値があるが、実績・数字・経験を捏造しない。
- 「AIに引用されるための裏技」「特定AIが特定検索エンジンを必ず使う」といった未確認前提を運用ルールにしない。

## 4. Trend-aware title selection

記事生成時は、タイトル候補を固定テンプレートで決めない。次の順で判断する。

1. 読者の現在の検索意図
2. 話題の鮮度と制度・市場の変化
3. HDNが提供できる独自の実務判断
4. 競合記事とのタイトル重複・同質化
5. 検索向けタイトルとSNS向けタイトルを分ける価値があるか

速報記事は制度名・変更点・日付を前に出し、実務記事は問題・対象者・判断軸を前に出す。数字は「数字があるから強い」のではなく、読者の判断材料になる場合だけ使う。

## 5. Quality gate

公開前に以下を確認する。

- タイトルだけで対象読者と得られる答えが想像できるか。
- 本文を読み終えたとき、タイトルに誇張がないか。
- 検索語を詰め込んでいないか。
- 数字・経験・固有性に証拠があるか。
- SNSタイトルはSEOタイトルの単なる短縮ではないか。
- 冒頭数段落でタイトルの問いに答えているか。
- H2/H3がタイトルの主張を回収しているか。
- 現在の制度・トレンドに照らして古い表現になっていないか。
